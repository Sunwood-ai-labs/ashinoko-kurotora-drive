# ゲームとコースの境界

## 配布単位

`dist/` はビルド済みバンドル専用のディレクトリではなく、そのまま配信するES Modules・HTML・CSS・GLB・JSONの集合です。フレームワークや外部CDNを必要としません。GitHub Pagesへはこのディレクトリだけを送ります。

### ゲーム側

- `game.mjs`：起動、UI、入力、セッション状態、カメラ、描画の接続
- `physics.mjs`：DOMから独立したコース補間・走行物理・自動操舵
- `appearance.mjs` / `vegetation.mjs`：ブラウザ向け材質、植生のインスタンス化・LOD
- `index.html` / `style.css`：操作画面とWebGL失敗時の案内
- `assets/kurotora.glb`：ゲームで使用する車体。コース契約からは独立
- `vendor/`：同梱した実行時ライブラリと原ライセンス

### コース側

`assets/course-manifest.json` を入口に、ルート・風景・植生の索引と座標規約を宣言します。`course-loader.mjs` がmanifest・データを検証して読み込み、ゲームへ渡します。コースパック自体はKUROTORAを参照しません。

既存の大きなGLBのURLは維持しています。ファイルが同じ `assets/` にあることと、責務が同じであることは別です。どのデータがパックに属するかはmanifestから辿れるようにします。

## 契約の版と座標

ゲーム版は `package.json` の0.2.0、コースは `courseId: ashinoko-gt` / `packVersion: 4.0.0`、契約schemaは1として別々に管理します。schemaは `dist/schemas/` にあります。

単位はメートル。ルート・配置はlocal Z-up、GLBはglTF Y-upで、表示への変換は `[x, z, -y]` です。距離は閉ループの3D折れ線距離、道路幅は7m、開始位置の推奨値は1250mです。ルートは既に路面高へ補正済みのため、元の+.14mを二重に加えません。描画用路面lift .014mは別の量です。

ブラウザは構造と値の検証を行います。全資源のSHA-256は `scripts/course-pack.mjs` とCIで照合し、ブラウザが毎回約110MBを再hashする仕様ではありません。

## 処理の流れ

1. WebGL 2を初期化。利用不能ならゲームの操作UIを止め、案内を表示
2. コース契約を読み込み、座標・単位・索引・経路を検証
3. 車体と路面、分割GLB、植生を読み込み
4. 物理計算は固定刻みで更新し、入力と自動操舵を切り替え
5. 描画へ位置・向き・速度を渡し、LODと追従カメラを更新
6. タブ離脱、一時停止、完走、描画コンテキスト喪失で走行を停止

## 将来コースを別リポジトリへ移す場合

- パックに属するデータ、schema、出典、チェックサムをまとまった版として管理する
- 車体・UI・物理エンジンをコース側へ混ぜない
- 読込契約に互換性がない変更では契約版を上げ、ゲーム側の対応をテストする
- 別originで配信する場合はCORS、許可URL、相対参照、キャッシュ更新を設計する。現在の同一origin・安全な相対pathの前提を勝手に緩めない
- ゲーム側でパックの版とチェックサムを固定してから公開する

現在、任意の第三者コースURLを入力して実行する機能は提供していません。
